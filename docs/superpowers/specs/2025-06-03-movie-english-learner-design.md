# 看电影学英语 Android 应用 — 设计文档

## 概述

一个 Android 应用，通过悬浮窗叠加在视频 App 上方，OCR 识别屏幕字幕，结合字幕文件定位播放位置，内置 llama 提供单词/句子解释，帮助中文用户在观影过程中学习英语。

---

## 1. 整体架构

### 1.1 组件划分

| 组件 | 说明 | 运行环境 |
|------|------|---------|
| 主 App（电影英语助手） | 悬浮窗 + OCR + llama + 字幕处理 | Android 手机 |
| 数据标注工具 | 独立 App，框选字幕区域标注训练数据 | Android 手机 |
| 训练管线 | OCR 模型训练 + 蒸馏/剪枝/量化 | PC/GPU 服务器 |

### 1.2 打包方案：全内置（方案 A）

所有模型文件打包进 APK，安装即用，无需网络下载。

- OCR 模型（量化后 ~3MB）
- llama 模型 Qwen 2.5 1.5B Q4_K_M（~1.2GB）
- 总 APK 体积约 1.5-2GB

### 1.3 屏幕捕获方案

- **默认**：MediaProjection API，每次使用弹系统授权对话框
- **可选**：AccessibilityService，手动在设置中开启，体验更流畅
- 用户可按场景选择

## 2. 悬浮窗 UI 设计

### 2.1 默认状态：底部字幕条

- 半透明背景，叠加在视频底部
- 显示当前 OCR 识别到的字幕文本
- 难词用**黄色下划线**标记，已学词用**蓝色下划线**标记
- 显示当前匹配到的时间戳
- 上滑展开 llama 对话面板，右滑隐藏

### 2.2 点击单词 → 单词解释弹窗

弹出内容：
- 单词 + 音标
- 中文释义（多义项）
- **词根词缀解析**（颜色区分：前缀蓝色、词根黄色、后缀绿色、复合词紫色）
- 例句
- 同根词/同类词扩展
- 操作：加入生词本 / 追问 llama

### 2.3 点击红点 → 整句解释面板

每条字幕开头有一个红色圆点，点击弹出：
- 原句
- 中文翻译
- 逐词拆解（每个词一个标签，难词黄色标记）
- 语法分析（主谓宾结构标注 + 口语/习语提示）
- 操作：收藏整句 / 追问 llama

### 2.4 上滑展开 → llama 对话面板

- 占据屏幕下半部分
- 顶部显示当前字幕上下文
- 对话式交互：用户输入问题，llama 流式回复
- 支持语音输入
- 对话历史保留在当前会话中

## 3. 字幕处理管线

### 3.1 导入 & 解析

支持格式：SRT、ASS/SSA、VTT、SUB

处理步骤：
1. 自动检测编码（UTF-8 / GBK / Latin-1）
2. 统一解析为内部结构：`[索引, 开始时间, 结束时间, 文本]`
3. 去除样式标签（ASS）、HTML 标签
4. 统一换行符，合并断句，过滤特效字幕

### 3.2 llama 预处理（后台异步）

每句字幕送 llama 批量分析，提取结构化 JSON：

```json
{
  "translation": "整句中文翻译",
  "grammar": "简短语法分析",
  "difficult_words": [
    {
      "word": "单词",
      "level": 1-5,
      "meaning": "中文释义",
      "morphology": {
        "prefix": "前缀及含义",
        "root": "词根及含义",
        "suffix": "后缀及含义"
      }
    }
  ],
  "idioms": ["习语/俚语解释"]
}
```

- 显示预处理进度条（当前句数/总句数 + 预估剩余时间）
- 支持后台运行，用户可切换界面
- 结果缓存到 SQLite，按电影组织，无需重复分析

### 3.3 用户词库融合

将 llama 标记的难词与用户历史行为交叉比对：
- 查过的词 → 调整等级
- 标记为已掌握 → 不再标记
- 首次出现的词 → 保持 llama 初始标记

### 3.4 运行时字幕匹配

```
OCR 输出文本 → 模糊匹配（编辑距离）→ 定位字幕条目 → 读取缓存 → 更新悬浮窗
```

- 有字幕文件时：OCR 用于校准定位
- 无字幕文件时：仅 OCR 识别 + 翻译解释（无定位功能）
- 用户可导入字幕文件来启用定位

## 4. 生词等级调节机制

### 4.1 核心规则

| 用户行为 | 效果 | 速度 |
|---------|------|------|
| 点击查看 | 等级立即跳到最高级 | 一次到位 |
| 展示但未点击 | 每次降 0.5 级 | 需连续忽略 6 次才归零 |
| 加入生词本 | 锁定最高级，不自动降级 | — |
| 标记已掌握 | 立即归零 | — |

### 4.2 初始等级来源

llama 预处理时根据词汇难度分级：
- 常见词：1-2 级
- 中难词：3-4 级
- 习语/俚语：5 级（最高）

### 4.3 自适应效果

- 新用户：依赖 llama 通用判断，标记较多
- 使用越多：个人词库越精准，只标记真正陌生的词

## 5. OCR 模型

### 5.1 模型架构

**CRNN**（CNN + RNN + CTC）

- CNN：提取视觉特征（卷积层 → 特征图）
- RNN/LSTM：序列建模（特征图 → 序列特征）
- CTC：解码输出文本（序列特征 → 字符序列）

### 5.2 输入/输出

- 输入：字幕区域裁剪图（H×W×3，缩放至固定高度 32px）
- 输出：英文字符序列（A-Z, a-z, 0-9, .,!?-'"" 等）
- 字符集：大小写英文字母 + 数字 + 常见标点

### 5.3 推理方案

| 项目 | 规格 |
|------|------|
| 推理引擎 | TFLite |
| 模型格式 | .tflite (INT8 全整数量化) |
| 模型体积 | ~3MB（量化后） |
| 推理耗时 | 30-80ms (GPU) / 50-150ms (CPU) |
| 内存占用 | ~50MB |
| 调用方式 | Android TFLite Java/Kotlin API |

### 5.4 推理流程

1. **屏幕帧获取**：MediaProjection → ImageReader 获取 YUV → 转 RGB Bitmap（~2-3 FPS 采样）
2. **字幕区域裁剪**：固定裁剪屏幕底部 1/5 区域
3. **预处理**：灰度化 → 缩放至高度 32px → 归一化 → Tensor 输入
4. **TFLite 推理**：Interpreter.run() → CNN + LSTM + CTC
5. **后处理**：CTC 贪婪解码 → 去重去 blank → 拼写纠错 → 去重（连续相同则跳过）

### 5.5 采样策略

- 字幕未变化：每 1 秒采样一次
- 检测到变化：提高到每 0.3 秒
- 连续 5 帧相同：回到慢采样
- 有字幕文件匹配时：OCR 仅用于校准
- 用户暂停视频：停止 OCR

## 6. llama 语言模型

### 6.1 模型选择：Qwen 2.5 1.5B

选择理由：
- **中英双语原生训练**：中文表达自然，Llama/Phi 中文能力偏弱
- **体量适中**：1.5B 参数，量化后 ~1.2GB，手机可运行
- **推理速度**：手机端 10-20 token/s，对话体感可用
- **生态兼容**：llama.cpp / MLC / VLLM 均支持
- **Apache 2.0 协议**：商用无顾虑

### 6.2 推理方案

| 项目 | 规格 |
|------|------|
| 推理引擎 | llama.cpp (GGUF 格式) |
| 模型格式 | .gguf (Q4_K_M 量化) |
| 模型体积 | ~1.2GB（量化后） |
| 推理速度 | 10-20 token/s |
| 内存占用 | 1.5-3GB |
| 调用方式 | JNI C++ 调用 |
| GPU 加速 | Vulkan / OpenCL |
| CPU 回退 | ARM NEON 优化 |

### 6.3 两种推理模式

**批量预处理**：
- 导入字幕时后台批量推理
- 每句送结构化 prompt → 输出 JSON
- 支持断点续处理
- 整部电影约 5-15 分钟

**实时对话**：
- 用户点击单词/红点或追问时触发
- 上下文包含当前字幕
- 流式输出（逐 token 显示）
- 对话历史保留在内存，超长自动截断

### 6.4 系统 Prompt

llama 扮演的角色：用中文解释英文的英语老师，中文母语者视角。

## 7. 数据标注工具

### 7.1 形态

独立 Android App，专门用于 OCR 训练数据标注。

### 7.2 核心功能

- **框选**：拖拽绘制字幕区域边界框，角点手柄微调
- **文本输入**：输入框内对应的英文字幕文本
- **截图导入**：从相册批量导入电影截图，或录屏自动抽帧
- **预标注**：用已有模型先跑一遍，人工只需修正错误
- **导出**：导出为标准 OCR 数据集格式（图像 + JSON 标注）

### 7.3 迭代闭环

```
截图收集 → 人工标注 → 训练模型 → 预标注新数据 → 人工修正 → 模型提升
```

循环迭代，数据越多预标注越准，人工工作量递减。

## 8. 模型优化管线

### 8.1 三阶段优化

#### 阶段 1：知识蒸馏（仅 OCR 模型）

- 大模型（如 TrOCR-Large）作为 Teacher
- 轻量 Student 模型学习 Teacher 输出分布（软标签）
- 收益：精度提升 2-5%
- 工具：PyTorch 自定义训练脚本

#### 阶段 2：结构化剪枝（OCR + llama）

- **OCR**：通道剪枝，减少 CNN 卷积核数量
- **llama**：注意力头剪枝 + 层剪枝（SparseGPT）
- 每次剪枝后微调恢复精度
- 收益：体积减少 20-40%

#### 阶段 3：量化（OCR + llama）

- **OCR**：INT8 全整数量化 → TFLite → ~3MB
- **llama**：Q4_K_M 量化 → GGUF → ~1.2GB
- 需校准数据集保证量化后精度

### 8.2 优化效果

| 模型 | 原始 | 剪枝后 | 量化后 | 精度损失 |
|------|------|--------|--------|---------|
| OCR (CRNN) | ~20MB | ~12MB | ~3MB | < 2% |
| llama (1.5B) | ~3GB (FP16) | ~2GB | ~1.2GB (Q4) | < 5% |

## 9. 使用流程

1. 打开主 App → 导入字幕文件（可选）
2. 如有字幕：后台 llama 预处理，显示进度条，可后台运行
3. 打开视频 App 播放电影
4. 悬浮窗自动叠加 → MediaProjection 捕获屏幕 → OCR 识别字幕
5. 匹配字幕文件定位播放位置 → 显示带难词标记的字幕
6. 点击难词查看解释（释义 + 词根词缀 + 例句）
7. 点击红点查看整句分析（翻译 + 逐词 + 语法）
8. 上滑展开 llama 对话面板自由提问
9. 系统自动学习用户词汇量，越用标记越准
10. 看完可回顾收藏的生词和句子

## 10. 技术栈

| 层 | 技术 |
|----|------|
| Android UI | Jetpack Compose / View |
| 屏幕捕获 | MediaProjection + ImageReader |
| OCR 推理 | TFLite (INT8 CRNN) |
| llama 推理 | llama.cpp (GGUF, JNI) |
| 本地存储 | SQLite（字幕缓存 + 用户词库） |
| 模型训练 | PyTorch + CUDA |
| 模型优化 | PyTorch pruning + llama.cpp quantize + TFLite Converter |
| 标注工具 | 独立 Android App（View-based） |
