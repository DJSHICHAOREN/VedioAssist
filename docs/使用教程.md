# 电影英语助手 — 完整使用教程

## 项目概述

本项目包含四个子项目，覆盖从数据标注、模型训练、模型优化到 Android 应用的全流程。

---

## 一、总体使用流程

```
标注数据 → 训练OCR模型 → 优化模型 → 部署到Android
     ↓
下载llama模型 → 剪枝量化 → 部署到Android
     ↓
导入字幕 → llama预处理 → 开始看电影学英语
```

### 环境要求

| 项目 | 要求 |
|------|------|
| Android 应用 | Android Studio Hedgehog+、JDK 17、Gradle 8.5、NDK（用于JNI编译）|
| 标注工具 | Android Studio（同上）|
| OCR 训练 | Python 3.10+、CUDA GPU（推荐）、8GB+ 显存 |
| llama 优化 | Python 3.10+、CUDA GPU、llama.cpp |

---

## 二、计划一：Android 主应用

### 2.1 产物

`app/` 模块，产出 `app-debug.apk` 或 `app-release.apk`

### 2.2 前置准备

1. OCR 模型文件：将 `ocr_model.tflite` 放入 `app/src/main/assets/models/`
2. llama 模型文件：将 `qwen2.5-1.5b-q4_k_m.gguf` 放入 `app/src/main/assets/models/`
3. llama.cpp 静态库：将编译好的 `libllama.a` 放入 `app/src/main/jniLibs/arm64-v8a/`

> 注意：OCR 模型和 llama 模型分别由计划三和计划四产出。如暂无模型，OCR 推理会失败但不影响其他功能；llama 推理同样无法使用。

### 2.3 编译安装

```bash
# 在项目根目录
./gradlew :app:assembleDebug

# 安装到手机
adb install app/build/outputs/apk/debug/app-debug.apk
```

### 2.4 使用步骤

1. **打开应用** → 看到主界面，两个按钮：「启动悬浮窗」「导入字幕文件」

2. **导入字幕**（可选但推荐）：
   - 点击「导入字幕文件」
   - 选择 `.srt` / `.ass` / `.vtt` 字幕文件
   - 看到导入进度提示
   - 后台自动开始 llama 预处理（分析难词、生成翻译、语法分析）
   - 预处理完成会有提示

3. **启动悬浮窗**：
   - 点击「启动悬浮窗」
   - 首次使用：授权「悬浮窗权限」→ 授权「通知权限」→ 授权「屏幕录制」
   - 悬浮窗出现在屏幕底部（半透明横条）

4. **打开视频 App 播放电影**：
   - 悬浮窗自动识别字幕并显示在底部横条
   - 难词用**黄色下划线**标记，已掌握词用**蓝色**标记

5. **查单词**：
   - 点击字幕中的任意单词 → 弹出解释气泡
   - 气泡包含：音标、释义、词根词缀拆解、例句
   - 可「加入生词本」或「追问 llama」

6. **看整句分析**：
   - 点击字幕开头的 **红点** 🔴
   - 弹出整句面板：翻译、逐词拆解、语法分析

7. **和 llama 对话**：
   - 在单词弹窗或句子面板中点击「追问 llama」
   - 或上滑字幕条展开对话面板
   - 在输入框输入问题，llama 流式回答

8. **结束使用**：
   - 通知栏下拉 → 停止服务
   - 或右滑悬浮窗隐藏

### 2.5 权限说明

| 权限 | 用途 | 必须 |
|------|------|------|
| 悬浮窗 | 显示字幕横条 | 是 |
| 屏幕录制 | 捕获视频画面做 OCR | 是 |
| 通知 | 前台服务保活 | 是（Android 13+） |
| 读取媒体 | 导入字幕文件 | 是 |

## 三、计划二：数据标注工具

### 3.1 产物

独立的 Android App（`annotation-tool/` 模块），用于标注电影字幕截图，生成 OCR 训练数据集。

### 3.2 编译安装

```bash
./gradlew :annotation-tool:assembleDebug
adb install annotation-tool/build/outputs/apk/debug/annotation-tool-debug.apk
```

### 3.3 使用步骤

1. **准备截图**：播放带字幕的电影 → 截取包含字幕的帧（可多截几张，覆盖不同字体和背景）

2. **导入截图**：
   - 打开标注工具
   - 点击「📸 导入截图」
   - 选择一张电影截图

3. **框选字幕区域**：
   - 在图片上拖拽绘制**红色边界框**，框住字幕文字
   - 拖拽四角圆点可微调边界框

4. **输入文本**：
   - 在底部输入框输入该字幕的**英文文本**（严格对应图片上的文字）

5. **保存标注**：点击「✓ 保存」

6. **继续下一张**：点击「▶」加载下一张未标注的截图，重复步骤 3-5

7. **导出数据集**：
   - 标注完所有截图后点击「📤 导出」
   - 数据集保存在 `Documents/ocr_dataset_<timestamp>/`
   - 结构：
     ```
     ocr_dataset_xxx/
     ├── images/
     │   ├── img_00001.jpg
     │   ├── img_00002.jpg
     │   └── ...
     └── annotations.json
     ```

### 3.4 annotations.json 格式

```json
{
  "version": 1,
  "format": "ocr_detection",
  "total": 100,
  "annotations": [
    {
      "image": "images/img_00001.jpg",
      "bbox": [0.1, 0.85, 0.9, 0.95],
      "text": "I gotta get out of here before sundown"
    }
  ]
}
```

`bbox` 是归一化坐标 `[left, top, right, bottom]`，值域 0-1。

### 3.5 组织训练/验证集

导出后，将数据手动分成 `train/` 和 `val/` 两个目录，供计划三训练使用：

```
training/data/
├── train/
│   ├── images/
│   └── annotations.json
└── val/
    ├── images/
    └── annotations.json
```

一般按 80% / 20% 分配。

## 四、计划三：OCR 训练管线

### 4.1 产物

训练脚本和优化脚本，最终产出 `ocr_model.tflite`（INT8 量化后的 OCR 模型）。

### 4.2 环境安装

```bash
cd training
pip install -r requirements.txt
```

### 4.3 使用步骤

#### 步骤 1：准备数据

确保 `config.yaml` 中的数据路径正确：

```yaml
data:
  train_annotation: "data/train/annotations.json"
  val_annotation: "data/val/annotations.json"
```

#### 步骤 2：训练

```bash
python train.py
```

- 使用 CTC Loss 训练 CRNN 模型
- 每个 epoch 后输出 `Train Loss` 和 `Val CER`（字符错误率）
- 自动保存最佳模型到 `output/best_model.pt`
- 支持早停（默认 15 个 epoch 无改善则停止）

#### 步骤 3：评估

```bash
python evaluate.py
```

输出：
```
Average CER: 0.0321
Exact Match Accuracy: 78.50%
```

CER 越低越好（< 5% 为可用）。

#### 步骤 4（可选）：知识蒸馏

```bash
python distill.py
```

用 TrOCR 大模型作为 Teacher，教 CRNN Student 学习更准确的输出分布。产物：`output/distilled_model.pt`

#### 步骤 5：剪枝

```bash
python prune.py
```

移除 30% 不重要通道 + 微调 10 个 epoch。产物：`output/pruned_model.pt`

#### 步骤 6：导出 ONNX

```bash
python export.py
```

产物：`output/ocr_model.onnx`

#### 步骤 7：INT8 量化 → TFLite

```bash
python quantize.py   # 查看转换命令
# 按提示执行：
pip install onnx-tf
onnx-tf convert -i output/ocr_model.onnx -o output/ocr_saved_model
# 然后执行 quantize.py 中打印的 Python 代码生成 TFLite
```

产物：`output/ocr_model.tflite`（约 3MB）

#### 步骤 8：部署

```bash
cp output/ocr_model.tflite ../app/src/main/assets/models/ocr_model.tflite
```

### 4.4 完整一键流程

```bash
python train.py && \
python distill.py && \
python prune.py && \
python export.py
# 然后手动执行 quantize 步骤
```

### 4.5 配置调优

| 参数 | 位置 | 说明 |
|------|------|------|
| `training.epochs` | config.yaml | 训练轮数，数据集小可增大 |
| `training.learning_rate` | config.yaml | 学习率，不收敛可降低 |
| `pruning.target_sparsity` | config.yaml | 剪枝比例，0.3 = 剪掉30% |
| `CNN 层数` | model/crnn.py | 如需更轻量可减少 Conv2d 层 |

## 五、计划四：llama 优化管线

### 5.1 产物

优化脚本，最终产出 `qwen2.5-1.5b-q4_k_m.gguf`（Q4 量化 llama 模型）。

### 5.2 环境安装

```bash
cd llama-optimize
pip install -r requirements.txt
```

### 5.3 使用步骤

#### 步骤 1：下载原始模型

```bash
python download_model.py
```

- 从 HuggingFace 下载 `Qwen/Qwen2.5-1.5B-Instruct`
- 保存到 `models/qwen2.5-1.5b-original/`
- 需要 HuggingFace 账号和 token（首次使用 `huggingface-cli login`）

#### 步骤 2：剪枝

```bash
python prune_llm.py
```

- 对注意力头按层渐进剪枝（浅层保留多，深层剪得多）
- 可选择移除最深层（`layer_keep_ratio.end: 0.6` = 保留 60% 的层）
- 产物：`models/qwen2.5-1.5b-optimized/`

#### 步骤 3：对比评估（可选）

```bash
python evaluate_before_after.py
```

对比剪枝前后的回答质量和 PPL 变化，确认精度损失在可接受范围。

#### 步骤 4：性能测试（可选）

```bash
python benchmark.py
```

对比剪枝前后的推理速度和内存占用。

#### 步骤 5：量化

```bash
# 先安装 llama.cpp
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp && cmake -B build && cmake --build build --config Release
cd ..

# 运行量化脚本
bash quantize_gguf.sh ./models/qwen2.5-1.5b-optimized Q4_K_M
```

产物：`models/qwen2.5-1.5b-optimized/model-Q4_K_M.gguf`（约 1.2GB）

#### 步骤 6：验证

```bash
./llama.cpp/build/bin/llama-cli \
    -m models/qwen2.5-1.5b-optimized/model-Q4_K_M.gguf \
    -p "You are an English teacher. Explain the word 'gotta' in Chinese." \
    -n 256
```

预期：流式输出中文解释，语意连贯。

#### 步骤 7：部署

```bash
cp models/qwen2.5-1.5b-optimized/model-Q4_K_M.gguf \
   ../app/src/main/assets/models/qwen2.5-1.5b-q4_k_m.gguf
```

### 5.4 量化级别选择

| 级别 | 大小 | 质量 | 适用场景 |
|------|------|------|---------|
| Q2_K | ~600MB | 明显下降 | 4GB 内存手机 |
| Q3_K_M | ~900MB | 轻度下降 | 4-6GB 内存手机 |
| **Q4_K_M** | **~1.2GB** | **损失极小** | **6GB+ 内存手机（推荐）** |
| Q5_K_M | ~1.5GB | 近乎无损 | 8GB+ 内存手机 |

## 六、常见问题

### Q1：没有 OCR 模型能先用 App 吗？

可以。OCR 识别会失败，悬浮窗不会显示字幕文本。但 llama 对话功能不受影响（如果已部署 llama 模型）。

### Q2：没有 llama 模型能用吗？

可以。字幕预处理会跳过，单词弹窗和句子面板中没有 llama 解释。OCR 字幕显示和字幕文件匹配功能不受影响。

### Q3：两个模型都没有怎么测试？

悬浮窗能正常显示（只是没有识别结果），UI 交互正常。可以先体验权限申请、字幕导入、悬浮窗叠加等基础流程。

### Q4：训练 OCR 模型需要多少数据？

建议至少 2000-5000 张标注样本。覆盖不同电影、不同字体、不同背景。越多越好。

### Q5：可以用其他 LLM 模型吗？

可以。修改 `llama-optimize/config.yaml` 中的 `model.name`，换成其他 HuggingFace 模型名。只要是 llama.cpp 支持的架构（Llama、Qwen、Mistral 等）即可。

### Q6：字幕预处理太慢怎么办？

- 减少 llama 推理的 `maxTokens`（在 `PreprocessPipeline.kt` 中，默认 512）
- 使用更小的量化级别（Q3 比 Q4 快约 30%）
- 预处理是后台任务，用户可以切换到其他界面等待
