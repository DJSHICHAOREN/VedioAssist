llama 推理架构

Qwen 2.5 1.5B 在 Android 上的推理方案
🦙 推理引擎
  • llama.cpp (GGUF 格式)
  • 通过 JNI 调用 C++ 推理
  • GPU 加速：Vulkan / OpenCL
  • CPU 回退：ARM NEON 优化
📊 量化方案
  • Q4_K_M（推荐）：~1.2GB，质量损失小
  • Q3_K_M（备选）：~900MB，轻度损失
  • Q2_K（极限）：~600MB，质量明显下降
  • 6GB 内存手机可用 Q4
⚡ 性能预期
  • 对话推理：10-20 token/s
  • 预处理（每句）：0.5-2s
  • 整部电影预处理：5-15 分钟
  • 内存占用：1.5-3GB

导入字幕时后台批量推理
每句送结构化 prompt
提取：难词、词根、翻译、语法

模型优化管线

针对 OCR 模型和 llama 模型的优化流程

三阶段优化
阶段 1：知识蒸馏（可选，用于 OCR 模型）
用大模型（如 TrOCR-Large）作为 Teacher，训练轻量 Student 模型
Student 学习 Teacher 的输出分布（软标签），比直接训练效果更好
输出：同架构但参数可更小的学生模型
适用：OCR 模型  |  工具：PyTorch 自定义训练脚本  |  收益：精度提升 2-5%
阶段 2：结构化剪枝
移除不重要的权重/通道/注意力头
OCR 模型：通道剪枝，减少 CNN 卷积核数量
llama 模型：注意力头剪枝 + 层剪枝，移除低重要性层
每次剪枝后微调恢复精度
适用：两者  |  工具：torch.pruning / SparseGPT  |  收益：体积减少 20-40%
阶段 3：量化
将 FP32 权重转为低精度整数
OCR 模型：INT8 全整数量化 → TFLite 格式 → 2-5MB
llama 模型：Q4_K_M 量化 → GGUF 格式 → ~1.2GB
两种模型都需校准数据集保证量化后精度
适用：两者  |  工具：llama.cpp quantize / TFLite Converter  |  收益：体积减少 50-75%
