OCR 推理架构

CRNN 模型在 Android 上的推理方案

推理引擎对比

TFLite
  • Google 官方，Android 原生支持
  • 可调用 GPU (OpenGL ES) / NNAPI
  • INT8 量化模型直接加载
  • 轻量级，无额外依赖
ONNX Runtime
  • 跨平台，PyTorch 模型直接导出
  • CPU / GPU / NNAPI 多后端
  • 支持 FP16 和 INT8
  • 推理性能与 TFLite 接近
NCNN
  • 腾讯开源，专为移动端优化
  • ARM NEON 手写汇编加速
  • 体积极小，无系统依赖
  • Vulkan GPU 加速
推荐：TFLite — Android 原生集成，无需额外 .so，INT8 量化支持最好，Google 长期维护。

OCR 推理流程

从屏幕帧到识别的完整流程
1
屏幕帧获取
MediaProjection 回调 → ImageReader 获取 YUV 帧 → 转 RGB Bitmap
采样频率：~2-3 FPS（字幕变化不会很快，无需实时帧率）
2
字幕区域裁剪
固定裁剪屏幕底部 1/5 区域（字幕通常在此位置）
可选：先跑一个轻量检测模型定位精确字幕框（初始版本可省略）
3
预处理
灰度化 → 缩放至固定高度（32px，保持宽高比）→ 归一化 [0,1] → 转为模型输入 tensor (H×W×1)
4
TFLite 推理
Interpreter.run() → CNN 提取特征 → LSTM 序列建模 → CTC 解码
输出：字符序列 + 置信度
预期耗时：30-80ms（GPU）/ 50-150ms（CPU）
5
后处理 & 去重
CTC 贪婪解码 → 去除重复字符和 blank token → 拼写纠错 →
与上一帧结果比对，相同则跳过（减少字幕匹配开销）
✓
输出：识别文本
"I gotta get out of here before sundown" → 送入字幕匹配模块

OCR 采样策略

降低功耗和计算开销
🎯 自适应采样
  • 字幕未变化时：每 1 秒采样一次
  • 检测到变化时：提高到每 0.3 秒
  • 连续 5 帧相同 → 回到慢采样
🔋 省电策略
  • 有字幕文件匹配时：OCR 仅用于校准
  • 无字幕文件时：正常频率 OCR
  • 用户暂停视频：停止 OCR
